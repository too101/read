# READ — Linux port (X11/Xlib)

พอร์ต [`read.asm`](../dos) (โปรแกรมอ่านข้อความภาษาไทยสำหรับ DOS) มาเป็น
โปรแกรม Linux เขียนด้วยภาษา C เรียก X11 (Xlib) ตรง ๆ — โครงสร้างเดียวกับ
พอร์ต[วินโดวส์](../windows) (asm ล้วน เรียก Win32 GDI ตรง ๆ): ตรรกะแกนกลาง
ทั้งหมด (byte classification, การแปลรหัส KU/TIS, การประกอบสระ/วรรณยุกต์
แบบ combining mark, สไตล์ WordStar, การสร้างตารางบรรทัด, ขีดจำกัดการเลื่อน
จอ) เขียนแยกอิสระจากพอร์ตวินโดวส์แต่ตรงกันทุกจุดเพราะแปลจากตรรกะเดียวกัน —
เปลี่ยนแค่ชั้น windowing/framebuffer จาก Win32 GDI เป็น X11 เท่านั้น

## สถานะ

**Build ผ่านสะอาด และยืนยันด้วยภาพหน้าจอจริงแล้ว** (รันใน X server แบบ
headless ด้วย Xvfb + `xdotool` + ImageMagick `import`): เปิดไฟล์ได้ วาดตัว
อักษรไทย การประกอบสระ/วรรณยุกต์ กรอบตาราง และสไตล์ WordStar ทุกแบบถูกต้อง
**ลากขยาย/ย่อหน้าต่างแล้วเนื้อหาปรับตามจริง** (ทดสอบลาก 640×475 → 960×570
เนื้อหาขยายเต็มพื้นที่ใหม่ถูกต้อง, ลากลงต่ำกว่าขั้นต่ำก็ไม่ crash แค่โดนตัดภาพ
ตามพื้นที่จริง) ไม่มี error จาก X11 ตลอดการทดสอบ

## Build

ต้องมี GCC และ libX11 dev headers:

```
sudo apt install build-essential libx11-dev   # Debian/Ubuntu
sudo dnf install gcc libX11-devel             # Fedora
sudo pacman -S base-devel libx11              # Arch
```

แล้วรัน:

```
./build.sh
```

หรือสั่งตรง ๆ:

```
gcc -O2 -o read src/read_linux.c -lX11
```

## วิธีใช้ / ปุ่มควบคุม

เหมือนพอร์ตวินโดวส์และเวอร์ชัน DOS ทุกประการ:

```
./read [ไฟล์]
```

ไม่ใส่ชื่อไฟล์ = แสดงหน้า help ในตัว · ลูกศรขึ้น/ลง เลื่อนทีละบรรทัด ·
PgUp/PgDn/Space/Backspace เลื่อนทีละหน้า · Home/End ไปต้น/ท้ายไฟล์ ·
ลูกศรซ้าย/ขวา เลื่อนแนวนอน 8 คอลัมน์ · `C` สลับรหัส KU/TIS ·
`F1` เปิด/ปิดหน้า help · `Q`/Esc ออกจากโปรแกรม (คลิกปุ่มปิดหน้าต่างก็ได้)

## หน้าต่างปรับขนาดได้ (resizable)

เริ่มต้นที่ 640×475 พิกเซล (80×24) เหมือนเดิม แต่ลากขยาย/ย่อได้แล้ว —
จำนวนคอลัมน์/บรรทัดคำนวณใหม่จากขนาดหน้าต่างจริงทุกครั้งที่ลาก (ฟอนต์บิตแมป
8×19 คงเดิมเสมอ ลากใหญ่ขึ้น = เห็นเนื้อหาเยอะขึ้น ไม่ใช่ตัวอักษรใหญ่ขึ้น)
ดัก X11 event `ConfigureNotify`: คำนวณคอลัมน์/บรรทัดใหม่ (ขั้นต่ำ 20×3),
สร้าง framebuffer/`XImage` ใหม่ตามขนาด, คงตำแหน่งเลื่อนจอเดิมไว้ (ไม่รีเซ็ต
กลับบนสุด) แล้ววาดใหม่ — ตั้ง `XSizeHints`'s `PMinSize` ไว้ด้วยเพื่อกัน
window manager ลากหน้าต่างเล็กกว่าที่ใช้งานได้จริง

## สิ่งที่ทำต่างจากเวอร์ชัน DOS โดยตั้งใจ

เหมือนพอร์ตวินโดวส์ทุกข้อ (ดู README ของ [`windows/`](../windows) สำหรับ
รายละเอียด): ไม่มีโหมด CGA/EGA/VGA/Hercules ให้เลือก, โหลดทั้งไฟล์ลง memory
ก้อนเดียว ไม่อ่านเป็นบล็อก 64KB, ไม่มี selftest (`/t`) และยังไม่รองรับ
ลาก-วางไฟล์

## ต่างจากพอร์ตวินโดวส์ตรงไหน

- เขียนด้วย C ธรรมดา ไม่ใช่ assembly ล้วนแบบพอร์ตวินโดวส์ — ใช้ X11 (Xlib)
  แทน Win32 GDI: framebuffer เป็น array ธรรมดา (`malloc`) blit ผ่าน
  `XImage`/`XPutImage` แทน DIB section/`BitBlt`
- ใช้ C มาตรฐาน/POSIX ตรง ๆ (`argv`, `malloc`, `fopen`) ไม่มีข้อจำกัดแบบ
  "no CRT" ที่ตั้งใจไว้เฉพาะพอร์ต asm บนวินโดวส์ เพราะ libX11 เองก็ผูกกับ
  libc อยู่แล้ว การเขียนเป็น asm ล้วนจะไม่ได้ประโยชน์ด้านขนาด/dependency
  เพิ่มขึ้นจริง (ดูรายละเอียดเหตุผลใน README ของ [`windows/`](../windows))
- หน้าต่างปิดโดยกดปุ่มปิด (X) ได้ถูกต้อง (ดัก `WM_DELETE_WINDOW`)
- หน้า help (`HELP_LINUX.TXT`) ปรับข้อความให้ตรงกับพอร์ตนี้ (`./read ไฟล์`
  แทน `read.exe ไฟล์`, เครดิตบอกว่าเป็น "Linux Port (X11)") ส่วนตารางคีย์/
  ตัวอย่างสไตล์/เครดิตฟอนต์เหมือนกับพอร์ตวินโดวส์ทุกไบต์

## สมมติฐานเรื่องจอภาพ

โค้ดสมมติว่า X display เป็น TrueColor ความลึกสี 24 หรือ 32 บิต (เกือบทุก
เครื่อง Linux ปัจจุบันเป็นแบบนี้) เพราะสีทั้งหมดที่ใช้เป็นโทนเทา (R=G=B)
เรื่อง byte order ของแต่ละความลึกสีจึงไม่กระทบสีที่เห็น

## โครงสร้างไฟล์

```
read                 โปรแกรมที่ build ไว้แล้ว (ต้องมี libX11 บนเครื่อง)
src/read_linux.c     ซอร์สโค้ดทั้งหมด
src/data.h           ฟอนต์ AXV 8x19 + ตาราง KU→TIS + ข้อความ help ที่ฝังไว้
                     (สร้างจาก gen_data.py -- ไม่ควรแก้ไฟล์นี้ตรง ๆ)
HELP_LINUX.TXT       ข้อความหน้า help ที่ใช้จริง (แก้ตรงนี้ได้ แล้วรัน
                     gen_data.py ใหม่ -- ดูคำเตือนเรื่องรูปแบบไบต์ด้านล่าง)
gen_data.py          สคริปต์สร้าง src/data.h ใหม่จาก ../dos/AXV.FON,
                     ../dos/KU.INC, ../dos/STATUS.INC และ HELP_LINUX.TXT
build_help_linux.py  สคริปต์ dev-time ที่ใช้แก้ ../windows/HELP_WIN.TXT
render_help.py       เป็น HELP_LINUX.TXT พร้อมเรนเดอร์เป็นภาพตรวจสอบก่อน
                     build จริง -- ไม่จำเป็นต้องรันเองปกติ, แต่ render_help.py
                     มีประโยชน์เดี่ยว ๆ ด้วยสำหรับตรวจสอบ HELP_LINUX.TXT
                     ก่อน build จริงหลังแก้ไข: `python3 render_help.py`
build.sh             สคริปต์ build บน Linux
```

⚠️ **`HELP_LINUX.TXT` ไม่ใช่ text ธรรมดา** — มีไบต์ TIS-620 ภาษาไทยปนกับไบต์
ควบคุมสไตล์ WordStar และไบต์วาดกรอบตาราง แก้ไขด้วย text editor ทั่วไปได้
แต่ต้องระวังไม่ให้ความกว้างคอลัมน์ของแต่ละแถวในกรอบเปลี่ยน (นับเฉพาะ
ตัวอักษรฐาน/tab เป็น 1 คอลัมน์ สไตล์/สระ-วรรณยุกต์/ไบต์กลืนนับเป็น 0) ไม่งั้น
กรอบจะเบี้ยว — แก้แล้วรัน `python3 render_help.py` เพื่อดูภาพผลลัพธ์ก่อน
`gen_data.py` เสมอ
