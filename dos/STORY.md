### เขียนโปรแกรม DOS ในปี 2026

สมัยก่อนตอนยังใช้เครื่องมือเขียนโปรแกรมของ Borland (เช่น Turbo Pascal) เวลามีเวอร์ชันใหม่ออกมา เราก็ต้องเปิดดูเอกสารว่ามีอะไรใหม่บ้าง จะมีไฟล์ README แนบมากับโปรแกรมเล็กๆ ชื่อ "README.COM" ไว้อ่านเอกสารพวกนี้ เพราะมันยาวหลายหน้า

แต่พอเป็นเอกสารภาษาไทย มีขั้นตอนเพิ่มเติม คือ ต้อง load โปรแกรมที่เรียกว่า Thai Driver ก่อน แล้วค่อยเรียก README ขึ้นมา แต่ก็ยังเจอปัญหาแสดงผลไม่ครบ 80 คอลัมน์ เพราะสระกับวรรณยุกต์ไทยมันถูกนับรวมเป็นตัวอักษรด้วย ไม่งั้นก็ต้องไปเปิดผ่าน Word Processor อย่าง RW หรือ CW แทน ซึ่งมีความเสี่ยงที่อาจจะเผลอไปแก้ข้อความในไฟล์โดยไม่ตั้งใจ

ตอนนั้นเคยคิดอยากทำโปรแกรมแบบ README ที่รองรับภาษาไทยด้วย ทำงานได้กับเครื่องไหนก็ได้ ไม่ต้องพึ่ง Thai Driver ไม่ต้องผูกกับระบบภาษาไทยของค่ายไหน แต่พอเข้ายุค Windows ความจำเป็นแบบนี้ก็ลดลงเรื่อยๆ เลยไม่ได้สานต่อ

จนมาถึงตอนนี้ ไปเปิดทดสอบซอฟต์แวร์เก่าๆ แล้วเจอเอกสารที่แนบมากับไฟล์ ความคิดเดิมก็กลับมาอีกครั้ง คราวนี้ไปเจอโปรแกรม TREAD ที่ทำแบบนี้ได้พอดี แต่ติดที่มันอ่านได้แค่รหัสภาษาไทยแบบสมอ. (TIS) เจอไฟล์รหัสเกษตร (KU) ต้องแปลงไฟล์ก่อนถึงจะเปิดได้ เลยลองเอาไปถาม ZCode ว่าพอจะมีวิธีทำให้มันอ่านรหัสเกษตรได้ไหม ปรากฏว่ามันไม่รู้จักรหัสเกษตรเลย เลยต้องสอนมันก่อน จนสุดท้ายมันแปลงโค้ด TREAD ให้อ่านไฟล์รหัสเกษตรได้สำเร็จ

TREAD เขียนด้วย Turbo C ใช้ BGI Graphics Library รองรับ Hercules/EGA/VGA ฟอนต์ขนาด 8x14 แสดงได้ 25 บรรทัดที่ความละเอียดเท่า EGA (แม้จะใช้กับ VGA ที่มีความละเอียดสูงกว่า) ขนาดโปรแกรมประมาณ 50K โปรแกรมนี้แสดงผลตัวอักษรตามรหัสรูปแบบ WordStar ที่ไฟล์ CW/RW ใช้เหมือนกันด้วย ทั้งตัวหนา ตัวเอียง ตัวขยาย (กว้างเป็น 2 เท่า) ขีดเส้นใต้เดี่ยว/คู่ ตัวยก/ตัวห้อย จะแสดงเหมือนตอนที่พิมพ์ ตอนนั้นเราจะเรียกกันว่า WYSIWYG (What You See Is What You Get)

ในเมื่อ ZCode มันเข้าใจการแปลงรหัสภาษาไทย และการเอาข้อมูลฟอนต์ภาษาไทยไปแสดงผลแบบจัดระดับแล้ว เลยเกิดไอเดียลองให้มันเขียนขึ้นมาใหม่ทั้งหมดเป็นภาษา Assembly เพราะคิดว่าน่าจะทำงานเร็วที่สุด เลือกฟอนต์ 8x19 เพื่อให้ได้ 25 บรรทัดบน VGA (แบบความละเอียด VGA จริงๆ) ส่วนโหมดการแสดงผลแบบอื่น จำนวนบรรทัดก็จะลดหลั่นกันไป ทำทั้งทีก็เลยรองรับลงไปถึง CGA เผื่อเอาไปใช้กับเครื่องเก่าๆ ได้ แม้จะเหลือแค่ 10 บรรทัดเพราะความละเอียดต่ำ (640x200) ก็ตาม โปรแกรมเขียนตัวอักษรแบบกราฟิกส์ โดยออกแบบให้เขียนข้อมูลลง memory ตรงๆ เพื่อให้เร็วที่สุด

ฟอนต์ไทยเอามาจากโปรแกรม AxThai เพราะชอบและอ่านง่าย แต่พอเป็นภาษาอังกฤษมันจะออกตัวหนา เวลาทำเป็นตัวหนาอีกทีจะทำให้อ่านยาก เลยไปหาฟอนต์ตัวบางขนาด 8x19 เหมือนกัน ได้ฟอนต์ของ DOS-V มาใช้แทน ส่วนอักษรสัญลักษณ์พิเศษก็เทียบกับฟอนต์ของ CW แล้วแก้ไขเพิ่มเอง งานแก้ฟอนต์ทำเองด้วยโปรแกรม Fontraption บน DOS

นอกจากนี้ ยังเพิ่มอัลกอริทึมอย่างง่าย เพื่อจะตรวจสอบว่าเอกสารภาษาไทยนี้เป็นรหัสเกษตรหรือสมอ. เพื่อที่เวลาเปิดมาจะได้แสดงผลได้ถูก แต่ถ้าไม่ถูกก็สามารถกดปุ่มเปลี่ยนรหัสได้ ซึ่งทดสอบกับเอกสารส่วนใหญ่ก็ตรวจสอบได้ถูก

ปรับกันอยู่หลายรอบกว่าจะทำงานได้ ระหว่างทางก็เจอ bug บ้าง ที่ Hercules บ้าง ที่ CGA บ้าง บาง bug ZCode ก็หาไม่เจอ หรือคิดนานมาก พอทำงานได้ระดับหนึ่งแล้ว ลองให้ ZCode ช่วยดูว่าทำให้เร็วขึ้นได้ไหม มันเสนอให้ย้าย memory ตอนเลื่อนหน้าจอแทนการวาดใหม่ทั้งหมด กับใส่ตาราง (แบบสูตรคูณ) แทนการใช้คำสั่งคูณเลขตรงๆ ซึ่งกิน clock เยอะ ทำให้เร็วขึ้นจริง พร้อม benchmark เทียบให้ดูด้วย ระหว่างนี้ยังเจอด้วยว่า CW กับ RW ใช้รหัสสำหรับอักษรตัวเอียงไม่เหมือนกัน เลยต้องทำให้รองรับทั้งสองแบบ
ระหว่างนั้นโปรแกรม NASM ในเครื่องมีอัพเดด version ทำให้ไม่สามารถสร้างโปรแกรม .COM ได้ถูกต้อง ZCode ก็งงกว่าจะเจอ ก็ใช้วิธีแก้ปัญหาเฉพาะหน้าไป

หลัง optimize รอบแรก โปรแกรมทำงานดีขึ้นมาก แต่ไปเจอ bug การแสดงผลบน DOSBox ไม่กระทบการทำงานหลักเท่าไหร่ และไม่แน่ใจว่าเป็นปัญหาของ DOSBox เองไหม แต่ให้ ZCode ไล่หาก็หาไม่เจอ ใช้เวลานานมาก เลยให้ export โค้ดทั้งหมดออกมาแล้วเอาไปลองถาม Claude Code ดู

โจทย์ที่ให้ Claude Code คือทำให้เร็วสุด เล็กสุด พร้อมแจ้ง bug ที่เจอ Claude Code ใช้เทคนิค optimize instruction เพิ่มเติม ลบโค้ดที่ไม่ได้ใช้ทิ้ง แล้วบีบอัดไฟล์ฟอนต์ ทำให้ขนาดโปรแกรมลดลงครึ่งหนึ่ง (จาก 15K เหลือ 7K) แถมยังหา bug ที่หาไม่เจอมานานเจอจนแก้ได้ด้วย จนกลายมาเป็นโปรแกรม "READ.COM" ตัวนี้
